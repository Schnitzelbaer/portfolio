## Context

The FDFA is Switzerland's foreign ministry. Besides diplomacy, it supports Swiss citizens abroad with a range of requests, such as ordering a new Swiss passport. Behind the scenes, many FDFA employees process these requests in complex internal specialist applications.

The Swiss federal corporate design defines the colors, typography and basic elements of government websites. For information-dense specialist applications, however, key building blocks are missing, for example complex tables and navigation, multi-step forms, or understated headers and footers.

The existing FDFA applications were built without a shared design foundation and look inconsistent as a result. A comprehensive design system is meant to bring them together.

## The challenge

A Swiss citizen abroad might order a passport once every ten years, often on their phone. That calls for clear guidance with few decisions per screen. Case workers at the FDFA, on the other hand, sit in front of the same screens every day and want to see as much as possible at a glance. The two user groups have little in common, yet both have to be served by the same design system.

## My role

I am the only UI designer on the project and responsible for building the design system. Variables, components and documentation are my work. Two UX designers at the FDFA design the web applications. They give me the domain context and concrete use cases that I align the library with. A software developer implements it in code.

## Solution: one library, four modes

A single library covers all applications. Each application runs in one of four modes: internal or external, each on smartphone or desktop. When the mode changes, the variables adjust font and component sizes automatically. The external applications have a generous header and top navigation, the specialist applications a very reduced header with side navigation.

The foundation is MudBlazor, the component library the developers work with. The Figma library follows its components so that design and code stay close together.

## One Figma file, optimized for AI

Development resources at the FDFA are scarce, so a software developer uses AI to translate the Figma components directly into MudBlazor code. This only works if the Figma file is structured so that the AI understands as much as possible without asking.

## Status and outlook

The system is in progress and partly live. Two internal FDFA software products are currently trying out the new components. It is too early for reliable figures on time saved, consistency or adoption. The system was built mainly for consular services. Other areas of the FDFA are to follow.
